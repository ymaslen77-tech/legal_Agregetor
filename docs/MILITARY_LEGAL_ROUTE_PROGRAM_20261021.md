# Военное право — рабочая программа и первый этап (21.10.2026)

**Обязателен LEGAL_ROUTE_STANDARD_V1 без ослабления требований.** Исходный объём Q&A на 15.10.2026 — 13 110 вопросов; это не живой спрос и не подтверждение юридической точности рубрик. Из анализа заголовков: контракт/служба 3 028; СВО 2 293; мобилизация/призыв 1 658; сигналы пересекаются.

## Этап 1 — реализовано в отдельном Draft PR
- Шесть маршрутов и 18 сценариев: контракт (3), увольнение (3), довольствие (3), ВВК (3), обращения к командованию (3), мобилизация/призыв (3).
- Реестр источников для каждого сценария, варианты результата CHECKLIST (15), DRAFT (2 запроса сведений только от самого военнослужащего), URGENT_INSTRUCTION (1).
- Read-only адаптер \`getMilitaryPreviewRoutes()\` к \`LEGAL_ROUTE_STANDARD_V1\`: канонические маршруты, URL сценариев, 17 связей на документы и стандартные исходы. Никакой записи в публичный реестр без юридической приёмки.\n- Детерминированные анкеты и проверка режима службы, статуса, событий, даты, документов, цели; запрет при неопределённом статусе, неверных/пустых полях. Нет LLM-выводов о праве на увольнение.
- DOCUMENT_RESULT_V1 с уникальной версией, `filingReady=false`, `legalRegistryReviewedAt=null` и обязательным `requiresLegalReview=true`.
- Матрица **11 обязательных пунктов по каждому из 18 сценариев**, все остаются неподтверждёнными, `expertSignOff=NOT_GRANTED`.
- Внутренний UI для локального `MILITARY_PREVIEW=1` (`/internal/military-preview/`; production всегда 404), версии в памяти вкладки, PDF/DOCX через существующие библиотеки. Контракт сохранения в общедоступном кабинете намеренно закрыт, пока новые маршруты не зарегистрированы юридически.
- Двоичная приёмка всех 17 PDF/DOCX с тестовыми данными: `npm run audit:military-files`; GitHub Actions загружает исходные файлы и манифест при успешной сборке. Это не экспертиза содержания или фактический допуск к подаче.
- Внутреннее тестирование не требует Neon. **Ни один маршрут не добавлен в публичный реестр, SEO-карты, навигацию или production.**

## Юридические источники — первичные публикации установлены, применимость НЕ подтверждена
- ФЗ № 53-ФЗ «О воинской обязанности и военной службе»: https://mchs.gov.ru/dokumenty/814
- ФЗ № 76-ФЗ «О статусе военнослужащих»: https://mchs.gov.ru/dokumenty/812 (ведомственная публикация редакции 04.08.2026)
- Указ Президента № 1237 «Вопросы прохождения военной службы»: https://mchs.gov.ru/dokumenty/804 (проверить последующие изменения)
- Постановление № 574 об независимой ВВЭ: https://mchs.gov.ru/dokumenty/693
- ФЗ № 306-ФЗ, Положение о ВВЭ № 565, Указ № 647, КАС РФ — только предварительный реестр, официальные консолидированные редакции и исключения пока НЕ согласованы: https://pravo.gov.ru/

Нельзя смешивать контракт, призыв, мобилизацию, служебные отношения в различных федеральных органах и специальные периоды. Не считать истечение срока контракта достаточным универсальным основанием увольнения; не исчислять сроки от неверной даты вручения; не обещать приостановления исполнения решения комиссии и не определять компетентный суд без проверки. Ни одна норма не объявлена правовым основанием для готового судебного документа.

## Что требуется до выпуска
1. Проверить оригинальные действующие тексты правовых норм с редакцией **на дату события**, специальные законы, президентские акты, ведомственные порядки; юрист проверяет все развилки.
2. 11 обязательных критериев: действующие источники; границы действия; статус заявителя; адресат/подсудность; сроки и момент начала; пошлина и суммы; приложения; текст требования; PDF/DOCX/версии; отрицательные/срочные и исключительные случаи; персональное экспертное согласование.
3. Реализовать конечную пользовательскую навигацию и генераторы только после содержательной правовой приёмки, подтвердить страницы, SEO, безопасность и автотесты на Chrome/Firefox/WebKit и мобильных устройствах.
4. Визуально инспектировать DOCX/PDF (переносы, кириллица, заголовки, даты, версии) и подготовить реальную проверку хранения версий в кабинете и прав доступа.
5. Протокол допуска с именем проверяющего, проверенными первичными актами, датой и решениями по каждому сценарию; без протокола `filingReady` не изменять и не публиковать.

Neon и production не изменять во время внутренней разработки.

## Этап 2: индивидуальная матрица вопросов для юридической экспертизы

Подготовлены **18 самостоятельных карточек предварительной проверки** в `src/data/military-case-reviews.ts`: правовой вопрос, применимый режим, полномочия, адресат, сроки и точка отсчёта, доказательства, исключения, сопоставленные акты. Для каждого сценария статус `PENDING_PRIMARY_TEXT_AND_CASE_SCOPE` и `NOT_GRANTED`. Это ревизия требований к проверке, а не заключение о правовой правильности. По сути, подлинное подтверждение актуальных норм, вступления в силу и допустимости документа остаётся обязательным.

Источники дополнены официальными страницами: Пленум ВС РФ №8 (https://www.vsrf.ru/documents/all/8382), изменения №21 от 28.10.2025 (https://www.vsrf.ru/documents/all/34814), ПП РФ №565 (https://mchs.gov.ru/dokumenty/553). Сверка первичного действующего текста необходима перед экспертным допуском.

### Проверка непубликации и SEO
Добавлен Playwright E2E `tests/e2e/military-isolation.spec.ts`: Production должен отвечать 404 на `/internal/military-preview/`; все 6 маршрутов и 17 документов не должны появляться в картах сайта или публичном каталоге. Для ссылок на общий портал `pravo.gov.ru` теперь явно отмечено `PRIMARY_DOCUMENT_LINK_PENDING` — это **не подтверждение источника**.

### Блокировка HTTP 200 от потокового notFound (регрессия E2E)
Исходный notFound() внутри динамического React Server Component возвращал не гарантированный HTTP 404: Playwright зафиксировал HTTP 200 при noindex. Для внутреннего пути добавлена отдельная ранняя проверка src/middleware.ts, возвращающая HTTP 404, x-robots-tag: noindex, nofollow и cache-control: no-store до React-рендеринга. В разработке при MILITARY_PREVIEW=1 путь разрешён, исключён из SEO-merge и не делает лишних обращений к Neon. Это обязательная часть релизной безопасности.

## Защищённый предпросмотр Vercel

При `MILITARY_PREVIEW=1`, установленном **только в Preview** для ветки `feat/military-legal-routes-v1-20261021`, и `VERCEL_ENV=preview`, серверный маршрут `/internal/military-preview/` разрешён на Vercel Preview. У проекта должна оставаться включённой Vercel Authentication для Preview; иначе нельзя распространять URL. В Production даже случайно заданное `MILITARY_PREVIEW=1` **не** откроет страницу (`VERCEL_ENV=production`); вернётся настоящий HTTP 404 через Middleware. SEO: noindex, не входит в Sitemap. Neon и основной публичный реестр не используются.

Разрешён только экспертный интерфейс подготовки и экспорта для проверки — все 18 сценариев `filingReady=false`, протокол 11 критериев и обязательное `expertSignOff=NOT_GRANTED` сохраняются. Нельзя использовать Preview как юридическую публикацию или делиться обходом Vercel Authentication. Проверка на `npm run test:military`.

Preview environment adjustment: Vercel may not expose system `VERCEL_ENV` when automatic system variable exposure is disabled. Preview therefore requires **both branch-scoped variables** `MILITARY_PREVIEW=1` and `MILITARY_PREVIEW_SCOPE=military-feature-preview`; explicit `VERCEL_ENV=production` still denies access. Vercel Authentication remains mandatory. The flags are set ONLY for Preview deployments from `feat/military-legal-routes-v1-20261021`.

## Эталон интерфейса — этап 3

- Утверждённые канонические URL `/problems/...` остаются **внутренней моделью данных**, не появляются в Sitemap до экспертной приёмки. Временно доступны 18 адресуемых предпросмотров только вида `/internal/military-preview/?route=<whitelisted>&scenario=<whitelisted>`. Факты пользователя в URL не передаются.
- Пошаговый интерфейс, обязательное подтверждение исходных фактов, юридические препятствия до генерации, общий `LegalFormField` и `LegalRouteJourney`, версии и экспорт по DOCUMENT_RESULT_V1.
- Для военного Preview отключена **любая** кнопка сохранения в постоянный кабинет: `DocumentResultSummary.showArchive=false`. Запрет серверной регистрации и отсутствие отправки в Neon сохраняются. Архив можно открывать лишь после подтверждённого допуска и проверки авторизации, шифрования, полномочий, целостности версии и согласия.
