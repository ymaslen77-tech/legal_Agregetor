## 1. Что именно принято за семейный эталон

Нельзя объявить один конкретный старый React-компонент полным эталоном семейного права: в проекте одновременно существуют **legacy-family**, **family-additive** и расширенные family/labor-маршруты. В части этих маршрутов конечный результат — чек-лист или предварительный проект. Копирование всех вариантов в военное право противоречило бы согласованному требованию «только юридически значимые документы».

Поэтому архитектурный эталон — существующие **контракты**:

1. `src/data/legal-route-standard.ts`: `LEGAL_ROUTE_STANDARD_V1`, `LegalRouteV1`, `LegalRouteScenarioV1`. Реестр содержит категорию, маршрут, конкретную ситуацию, требуемые входные поля, результат, постоянные адреса страницы и документа; legacy-путь явно помечается.
2. `src/lib/document-result-contract.ts`: `DOCUMENT_RESULT_V1`. Структурированный документ несёт версию, дату, категорию/маршрут/ситуацию, тип результата, источники/правила, текст и правдивый статус `filingReady: false`.
3. `src/data/family-additive-routes.ts` и `src/components/documents/FamilyAdditiveProblemPage.tsx`: выбор конкретной ситуации раньше ввода данных; отдельная каноническая страница документа `/documents/[documentSlug]/`.
4. `src/lib/family-additive-validator.ts` и `src/lib/parents-child-validator.ts`: условная проверка обязательных сведений, статус заявителя, надлежащий способ защиты, проверка подсудности/компетенции; неизвестные обстоятельства не заполняются автоматически.
5. `src/data/family-additive-legal-review.ts` и `src/data/parents-child-legal-review.ts`: конкретные записи правовых правил (ID, статья, формулировка, официальный источник/URL, граница применения, ограничения, дата проверки), привязанные к ситуации.
6. `src/lib/family-additive-document.ts`, `src/lib/parents-child-document-result.ts`, `src/lib/family-additive-pdf.ts`, `src/lib/document-export.ts`: разные виды исходов, юридически маркированные черновики, PDF и/или DOCX; официальные формы не подменяются выдуманным бланком.
7. `src/lib/document-version-history.ts`, `src/components/documents/DocumentVersionHistory.tsx`, `src/components/documents/DocumentResultSummary.tsx`, `src/components/documents/SaveLegalDocumentButton.tsx`: иммутабельные версии, юридический статус и **необязательное** сохранение по явному действию пользователя.
8. `src/app/problems/[category]/[slug]/page.tsx` и `src/app/documents/[documentSlug]/page.tsx`: отдельные страницы ситуаций/результатов, SEO-метаданные, ссылки и видимость источников.

**Оговорка:** техническое наличие ссылок на нормы и маркировка проекта не доказывают правильность правовой позиции. Сам эталон содержит оговорки и неполные проекты. Военный маршрут должен отвечать его *строгим техническим правилам*, но не копировать недоработки семейных черновиков.

## 2. Фактический baseline военного права

- 20 тематических категорий, 143 ситуации, из них 22 информационные, 102 документные, 19 смешанные.
- Для 121 документной/смешанной ситуации предусмотрена необходимость решения о документе; пока реализовано **18 прототипов** генераторов, **103 без генератора**.
- У всех ситуаций `legalReviewed: false`; `documentSlugs: []` не связывает маршруты с самостоятельными документными страницами.
- В `src/data/military-document-candidates.ts` есть 18 целевых формулировок требований, но используется **пять общих классов** текстового шаблона: `REQUEST_COPY`, `VVK_REVIEW`, `REPORT`, `COMPLAINT`, `PAYMENT_REQUEST`.
- `src/components/documents/MilitaryDraftForm.tsx`: PDF/DOCX, минимальные общие поля, история версий лишь в текущей вкладке; **не используется** `DOCUMENT_RESULT_V1`.
- `src/lib/military-situation-content.ts`: часть процедурных шагов строится по общим регулярным выражениям заголовка, а не по индивидуальному юридическому плану.
- `src/data/military-guidance.ts`: нормы в первую очередь на уровне категории; отдельной юридической матрицы по каждой ситуации нет.
- `src/data/military-related-links.ts`: реализована перелинковка категорий, ситуаций и **реальных** якорей генераторов. Предыдущий CI подтвердил 300 ссылок между ситуациями, 70 межкатегорийных переходов, 62 ссылки на существующие генераторы, 0 несуществующих целей.
- `src/data/military-release-readiness.ts`: закрытый по умолчанию gate; успешный `next build` не считается юридической приёмкой.

## 3. Стандарт одной полностью разработанной ситуации

Для **каждой** из 143 ситуаций обязателен индивидуальный контракт. Наличие полей в интерфейсе не равно разрешению использовать документ.

| Область | Обязательное свойство |
|---|---|
| Адрес | Постоянный `/voennoe-pravo/[category]/[situation]/`, уникальный заголовок, каноническая ссылка, корректные обратные переходы |
| Контекст | Уже выбранная ситуация, правовой режим и цель обращения известны без повторного ввода |
| Квалификация | Вид службы, статус заявителя, временная применимость, правовые условия, компетентный орган, порядок защиты и запреты |
| Выход | Только информационное разъяснение, **если документ не нужен**, либо **точно определённый юридический документ**. Чек-листы и анкеты не являются итоговыми документами |
| Документ | Уникальный `documentSlug`, вид (`RAPORT`, `APPLICATION`, `COMPLAINT`, `ADMINISTRATIVE_CLAIM`, `CIVIL_CLAIM`, `PROCEDURAL_MOTION`, `PROCEDURAL_APPEAL` и др.), точное требование, адресат, основание, доказательства, приложения, реквизиты, подпись |
| Поля | Только **отсутствующие** конкретные факты и реквизиты нужного документа; условные поля лишь по законному ответвлению; без вторичного вопроса «Что произошло?» |
| Право | Перечень индивидуально применимых правовых норм: ID правила, официальный опубликованный источник, редакция и дата сверки, границы применения, исключения и срок |
| Результат | Формат `DOCUMENT_RESULT_V1` с ID версии, временем, документным адресом, `usedRuleIds`, типом результата, действительным статусом проверки |
| Экспорт | Реальные PDF и DOCX с одним и тем же проверяемым текстом, кириллицей, реквизитами и приложениями; отсутствие дублирования и повреждений |
| Версии | Сохранение снимка при явном формировании новой версии. Архив в личном кабинете — только по отдельному согласию и с защитой данных |
| Навигация | Ситуации до/после, сопутствующие темы, нужные доказательства, смежные документы, двусторонние переходы; ноль мёртвых ссылок |
| SEO | Уникальные title/description, breadcrumbs, метаданные и внутренние ссылки; **noindex до индивидуальной юридической приёмки** |
| Ограничения | Не обещать исход дела, выплату или увольнение; не заменять официальный бланк произвольным текстом; не выдавать черновик за готовый к подаче |

### Важные структурные решения

1. Сохранить существующие пути `/voennoe-pravo/` и 143 slug, чтобы не терять уже созданную структуру и внутренние ссылки.
2. После утверждения каждого **конкретного** генератора создать и связать `/documents/[documentSlug]/`; текущий якорь `#military-document-preparation` оставить переходным, пока нет канонической страницы.
3. Новые документные результаты привести к `DOCUMENT_RESULT_V1` и общему UI-отображению статуса. Не устанавливать `filingReady: true` в обход контракта.
4. Документные поля определяются юридической спецификацией ситуации. Заголовки по ключевым словам не могут быть источником процессуальной формы.
5. Различать `PENDING`, `VERIFIED`, `BLOCKED`; утверждённая категория **не** означает, что все её ситуации проверены.
6. Опциональная передача юристу — только с явным согласием и без автоматической отправки персональных/военных данных.

## 6. Примечание о согласованном UX

Военный маршрут — сервис подготовки **юридических документов**, не анкетирования. Разрешены только минимальные поля реквизитов и фактов документа. После выбора ситуации интерфейс не спрашивает заново её суть и не выдаёт чек-лист вместо рапорта/заявления/иска. Если правового основания для документа нет, показывается адресное разъяснение без фиктивного генератора.
