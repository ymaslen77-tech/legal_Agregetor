# Военное право — интерфейс и связывание генераторов, промежуточная приёмка этапов 5–9

**Дата:** 29 октября 2026 года  
**Ветка:** `feature/military-rebuild-from-zero-20261027` (PR № 25, Draft)  
**Граница работ:** разработка и тестирование без публикации на `pravopoisk.ru`.

## Что изменено

1. Добавлен `src/components/documents/MilitaryDraftWorkbench.tsx` — единый пользовательский редактор для подготовленных 121 внутренних композиций (рапорты, заявления, жалобы, процессуальные проекты).
2. Используется `military-document-core.ts`, а не второй конкурирующий генератор. Выбранная ситуация определяет тип и предмет обращения, пользователь вводит только фактические реквизиты и индивидуальные сведения. Обязательные поля валидируются, создание неутверждённого правового вывода запрещено.
3. Подключено редактирование текста и создание новых снимков через семейный формат `DOCUMENT_RESULT_V1`, максимум 6 версий в оперативной памяти вкладки. Данные **не сохраняются** в личный кабинет, базу, localStorage или URL.
4. Экспорт PDF/DOCX вызывается через `military-document-export.ts` с проверкой принадлежности документа, идентификатора версии, статуса черновика, отсутствия юридического одобрения, а не через старый неконтролируемый экспорт.
5. В `src/app/voennoe-pravo/[slug]/[situation]/page.tsx` подключение **закрыто флагом**. Только на локальном Next.js dev-сервере с `ENABLE_MILITARY_DRAFT_PREVIEW=true` отображается новый конструктор. В production builds условие строго ложно даже при случайном включении переменной. В отсутствие флага прежние 18 форм работают как до изменений, остальные 103 остаются без формы.
6. Все страницы военного права получили персональную секцию «Что проверить именно по этому вопросу» из правовой матрицы на 143 ситуации, включая предмет, доказательства, адресата и ограничения. Это редакционные сведения, не юридически утверждённая консультация.
7. Тестовые внутренние связи для 121 генерируемой ситуации ведут на существующие адреса страниц с якорем `#military-document-preparation`. В обычном режиме возвращаются только ссылки на 18 старых форм, поэтому публичные страницы не ведут к скрытым генераторам.
8. Добавлена unit-проверка `military-preview-access.test.ts`, расширена `military-related-links.test.ts`. Подготовлены браузерные сценарии `military-draft-preview.spec.ts` для 5 типов документов и `military-catalog.spec.ts` для 20 категорий.

## Как запустить локальную проверку (без персональных данных)

В локальном рабочем каталоге проекта, в отдельной development-среде:

```sh
ENABLE_MILITARY_DRAFT_PREVIEW=true npm run dev
npm run test:military
npm run typecheck
npm run lint
ENABLE_MILITARY_DRAFT_PREVIEW=true npm run test:e2e:military-preview
```

На Windows PowerShell переменная задаётся как `$env:ENABLE_MILITARY_DRAFT_PREVIEW="true"` и далее запускается `npm run dev` либо тестовый скрипт. Для Playwright нужны установленные зависимости Chromium и доступный локальный сервер. Не направлять на QA реальные медицинские или персональные документы.

## Критерии самопроверки

- 121 спецификация и 121 существующая композиция в внутреннем ядре.
- Для 22 информационных страниц форма не создаётся.
- Ни один проект не становится `filingReady=true` и не получает `legalRegistryReviewedAt`.
- Сохраняются реальные PDF/DOCX и редактирование только с предупреждением о необходимости юридической проверки.
- Превью-генераторы не открыты в `NODE_ENV=production`, даже при наличии флага.
- 121 тестовая ссылка привязана к существующей странице и якорю; все 143 ситуации имеют индивидуальные редакционные инструкции.

## Незавершённые задачи для выпуска

**Юридическая экспертиза:** точные действующие нормы, редакции, применимость и утверждение 143 ситуаций и 121 текста. Этим изменением не закрыта.

**Полноценный кабинет:** постоянное хранение версий и безопасный доступ с авторизацией не реализованы; нельзя безопасно включать обработку персональных данных без аудита схемы хранения, политики доступа и согласий.

**Интеграционный QA:** браузерный прогон на реальном Next.js dev/preview и проверка PDF/DOCX внешними просмотрщиками должны быть выполнены и задокументированы.

**Деплой:** Coolify, сервер, база данных, секреты и основная ветка не изменяются. PR №25 оставляется Draft до проверки и явного согласования выпуска.

**Примечание о правовых статусах:** вся новая автоматизация остаётся инструментом подготовки *неутверждённого черновика*, а не готового документа для подачи.
