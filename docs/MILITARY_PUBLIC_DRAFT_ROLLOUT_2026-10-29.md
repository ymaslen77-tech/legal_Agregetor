# Военное право — подготовка всех 121 черновых генераторов к production

Дата: 29.10.2026. PR #25 остаётся Draft. Рабочий VPS не затронут.

## Режим запуска
- По умолчанию `ENABLE_MILITARY_PUBLIC_DRAFTS` не задан: production показывает прежние 18 форм.
- После CI и изолированной проверки VPS выставить `ENABLE_MILITARY_PUBLIC_DRAFTS=true` одновременно **при сборке Next.js и на работающем сервере**; требуется пересобрать образ, поскольку страницы статически формируются при build.
- В development доступ 121 форме по-прежнему только с `ENABLE_MILITARY_DRAFT_PREVIEW=true`. Этот флаг не открывает production.
- Один серверный переключатель контролирует доступ к формам, редактору архивных версий и POST в зашифрованный архив. Сохранение только по кнопке; нужны авторизация и шифрование.
- Rollback: снять production-флаг, пересобрать образ. Ранее сохранённые архивные версии остаются зашифрованными и доступны владельцам.

## Безопасность юридического статуса
Все новые документы остаются `DRAFT`, `filingReady=false`, `requiresLegalReview=true`, `legalRegistryReviewedAt=null`, `usedRuleIds=[]`. В тексте и экспортируемых PDF/DOCX — заметная отметка, что проект не готов к подаче. Даже два сверенных источника подтверждают только проверяемый тезис, не готовность индивидуального документа. Для 22 информационных ситуаций форма отсутствует. Материалы всё ещё `noindex`.

## Финальный путь
1. На последнем коммите выполнить статические проверки, все 121 dev-формы в браузере, интеграцию архива и новый smoke-test production-сборки с флагом.
2. Изолированный Coolify preview на российском VPS без production-секретов и доступа к рабочей БД: HTTP, ссылки, редактор, PDF/DOCX, логин, сохранение, контроль изоляции пользователей.
3. Только после успешных проверок и отдельного решения о публикации включить флаг на рабочем VPS и убедиться в фактическом обновлении образа. Не использовать GitHub Actions как CD.
