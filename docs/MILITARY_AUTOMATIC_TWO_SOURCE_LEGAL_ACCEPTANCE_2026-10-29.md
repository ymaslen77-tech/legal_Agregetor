# Военное право — упрощённая юридическая приёмка по двум источникам

**Дата:** 29.10.2026. **Ветка:** `feature/military-rebuild-from-zero-20261027`. **PR:** #25 (Draft).

## Новое правило — юридическая приёмка без отдельного согласующего лица

Отменён глобальный ручной список из 143 «юридических подписей» и 121 «подписей документа», блокировавший техническую готовность проекта. Вместо него вводится **автоматическая оценка каждого конкретного правового утверждения по источникам** в `src/data/military-source-verification.ts`.

### Достаточно двух независимых источников

- Два фактически открытых и сопоставленных источника (официальные **или** авторитетные юридические системы) с совпадающими положениями — **`VERIFIED_OFFICIAL`** или **`VERIFIED_REPUTABLE`**. Ручная подпись юриста после этого не нужна.
- При расхождении опубликованного действующего официального акта с неофициальным пересказом приоритет официальному тексту. Для принятия тезиса всё равно нужны **два независимых подтверждения**, согласующихся с официальной позицией; если официальная позиция опровергает тезис — `OFFICIAL_CONFLICT`, этот тезис нельзя помечать проверенным.
- Если официальные источники противоречат друг другу — `OFFICIAL_CONFLICT` (возможно разные редакции/сферы применения); если между авторитетными системами остаётся расхождение без разрешающего официального текста — `SOURCE_CONFLICT`.
- Один источник, разные URL одного издателя, ненадёжный сайт или ссылка без реально прочитанного текста **не создают подтверждения**.
- В результате остаются только статусы **«проверено по источникам»**, **«недостаточно источников»**, **«противоречия»**. Обязательного самостоятельного статуса «утверждено юристом» нет.

### Документирование без ручного согласования

Для каждого утверждения сохраняются конкретный тезис, источник, URL статьи/пункта, дата и редакция, проверенный фрагмент, результат «поддерживает/противоречит». Агрегатор сам вычисляет статус на основании двух независимых редакционно подтверждённых записей. Механизм не скачивает тексты в момент рендеринга сайта; **первичную фактическую сверку текста и фрагментов необходимо выполнить**. Ссылку на портал без чтения нельзя превращать в `opened:true` — это будет ложная приёмка.

Допустимые авторитетные платформы для соответствующих случаев: `consultant.ru`, `garant.ru`, `rg.ru`; официальные домены включают `pravo.gov.ru`, `publication.pravo.gov.ru`, `minjust.gov.ru` и компетентные государственные органы. Незнакомый домен не считается достоверным по умолчанию.

**Важное разграничение:** подтверждение точного юридического тезиса — не гарантия правоты индивидуального требования, наличия доказательств, правильности адресата, компетенции суда или возможности подачи судебного документа. Индивидуальные черновики по-прежнему получают `filingReady=false` и соответствующее предупреждение. Эта мера касается фактической корректности материалов, не является профессиональной юридической консультацией для конкретного пользователя.

## Изменения технической приёмки

- `getMilitaryReleaseReadiness()` больше **не использует** `legalReviewConfirmed`, `officialTextVerified`, `generationEnabled` как глобальные ручные препятствия выпуску каталога.
- Новый `catalogDeployable` — структурная готовность безопасного каталога, 20 категорий / 143 ситуации / 121 внутренних прототипов. Неподтверждённые положения остаются помеченными и `noindex`; новые 103 формы по-прежнему скрыты в production.
- `productionReady` теперь зависит от реальной технической готовности всех публичных генераторов, а не от ручного согласования 143 карточек. На момент изменения публичных генераторов **18/121**: для полного функционального выпуска этот флаг остаётся **false по техническим причинам**, а не из-за «непроставленной юридической галочки».
- `sourceAcceptance.manualSignOffRequired=false`, `globalSourceGateBlocksCatalog=false` и отдельные показатели подтверждённых, ожидающих, конфликтных ситуаций.
- На странице ситуации отражается статус по источникам. Подтверждённый тезис сопровождается адресами источников; до реальной сверки стоит текст «источники ещё сверяются».
- `getMilitaryDraftPlan()` больше не выбрасывает исключение из-за прежнего поля ручного одобрения.

## Первичная очередь — без выдумывания одобрений

`getMilitarySourceReviewQueue()` автоматически объединяет имеющиеся карты норм и ссылки-кандидаты в **143 строки** по всем 20 категориям. Из них 64 ранее имели сопоставления с неофициальными текстами, 79 — предварительный редакционный подбор. В обоих случаях в старых записях **нет доказанной полной сверки двух независимых фактических фрагментов для каждого тезиса**.

**Текущий статус: 1 автоматически подтверждённый конкретный тезис из 143 ситуаций.** Начальная проверка завершена для календарного срока призыва 2026 года (только этот факт, не вся юридическая ситуация): пункт 4 статьи 1 № 412-ФЗ, подтверждён двумя фактически открытыми независимыми правовыми системами. Остальные 142 ситуации пока ожидают подтверждения; не надо добавлять фиктивные отметки. Новые подтверждения принимаются **без ручного согласования**.

## Пример подтверждённого тезиса

Календарный период призыва: [КонсультантПлюс — пункт 4 статьи 1 № 412-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_518062/3d0cac60971a511280cbba229d9b6329c07731f7/) и [ГАРАНТ — тот же закон и пункт](https://www.garant.ru/products/ipo/prime/doc/412886361/). В обоих источниках воспроизведена идентичная норма. Официальный URL публикации известен, но сам текст портала не удалось открыть в данной проверке. Поэтому присвоен **VERIFIED_REPUTABLE**, а не **VERIFIED_OFFICIAL**. Отдельные сроки отправки и исключения этим тезисом не подтверждались.

## Автопроверка

`npm run test:military` включает `military-source-verification.test.ts`:
- 2 официальных/авторитетных подтверждения → автоматически проверено;
- 2 авторитетных источника без официального открытия → автоматически проверено, отдельно от признака официальной публикации;
- одна ссылка, непрочитанный документ, неизвестный домен, два URL одного издателя → не проверено;
- при противоречии официального и неофициального текста приоритет официальному;
- при конфликте самих официальных документов → не проверено;
- очередь содержит ровно 143 уникальных вопроса без маскировки отсутствующих сверок.

**Публикация и VPS:** в этом изменении нет merge, запуска Coolify, изменения секретов, миграций БД или обработки реальных персональных данных.
